# WorkBuddy Commercial GA v1.0 实施计划

## 1. 阶段目标

从 Production Pilot v0.4 推进到可正式签约、收费、支持和扩量的 Commercial GA v1.0。

目标不是继续增加演示功能，而是完成四件事：

1. 在真实组织环境中取得 Gate B、C、D 和 Production Open 的证据与签署；
2. 用小规模真实用户验证产品质量、稳定性、安全性和商业价值；
3. 补齐商用必需的租户管理、计费、支持、合规和运营能力；
4. 建立可重复的客户上线、专家团配置、Skill 发布和扩容流程。

GA 的标准闭环：

> 组织开户 → 身份与邮箱连接 → 专家团配置 → 影子试点 → Agent 执行 → 老板审批 → 真实发送 → 价值与风险报告 → 扩量或回滚

---

## 2. 计划周期

建议周期：12 周。

| 阶段 | 时间 | 目标 | 主要发布门 |
|---|---:|---|---|
| Phase 0 | 第 1 周 | 组织、供应商和责任人到位 | Pilot Start |
| Phase 1 | 第 2–3 周 | 真实生产环境与邮箱影子试点 | Gate B |
| Phase 2 | 第 4–5 周 | 真实模型、Agent 与质量评估 | Gate C |
| Phase 3 | 第 6 周 | 受控真实发送与故障演练 | Gate D |
| Phase 4 | 第 7–8 周 | 白名单生产试点 | Production Open |
| Phase 5 | 第 9–10 周 | 商用产品化 | Commercial Readiness |
| Phase 6 | 第 11–12 周 | 首批付费客户与 GA 决策 | GA Go/No-Go |

---

## 3. Phase 0：试点启动与责任冻结

### 必须完成

- 任命 Product、Platform、Security、Privacy、Operations、AI Platform 负责人；
- 为三个首发专家团指定真人业务负责人；
- 确定 5 个试点邮箱和 10–20 名后续白名单用户；
- 冻结首批 Workflow、Skill、工具和审批矩阵；
- 确定模型供应商、数据处理区域和保留政策；
- 确定 Google Cloud、Microsoft Entra、DNS、TLS、数据库、对象存储和 Secrets Manager 负责人；
- 确定事故处理、值班和真实发送最终责任人；
- 签署 Pilot Charter。

### 交付物

- 责任人 RACI；
- 试点范围清单；
- 专家团与 Workflow 发布清单；
- 数据处理和保留决策；
- 发送白名单与限额；
- Pilot 风险登记表。

### 退出标准

所有外部账号和责任均有明确持有人；没有“由开发团队代为决定”的高风险事项。

---

## 4. Phase 1：真实生产环境与 Gate B

### 生产基础设施

- 部署独立 production PostgreSQL、S3、Secrets Manager；
- 配置 OIDC/JWKS；
- 配置正式域名、TLS 和公网 webhook；
- 部署 API、Worker、Scheduler、Outbox Publisher；
- 接入 Prometheus、日志、Trace 和告警；
- 执行备份恢复、RLS、Outbox 重放、密钥轮换和紧急停止演练；
- 配置容量阈值和成本告警。

### 邮箱影子试点

- 连接真实 Gmail 和 Microsoft 365 邮箱；
- 完成初始同步、增量同步、watch/subscription 续订；
- 演练重复、乱序、丢失通知和游标过期；
- 验证移动、删除、标签和文件夹变化；
- 运行至少 5 个连续工作日影子模式；
- 由真人标注调度结果和高风险识别结果。

### Gate B 指标

| 指标 | 门槛 |
|---|---:|
| 测试范围漏邮件 | 0 |
| 重复邮件 | 0 |
| 游标恢复演练 | 100% 通过 |
| 主责专家团准确率 | ≥ 90% |
| 高风险漏报 | 0 |
| 低置信度人工复核 | 100% |
| 连续稳定运行 | ≥ 5 个工作日 |

### Gate B 签署

- Product Owner；
- IT Admin。

未通过 Gate B 时，不得开放自动规划或真实发送。

---

## 5. Phase 2：真实模型、Agent 与 Gate C

### 模型运行

- 接入正式模型账号；
- 记录模型、版本、输入输出哈希、延迟、Token 和成本；
- 配置主模型、降级模型、超时和预算；
- 对敏感数据执行脱敏或受控处理；
- 完成模型供应商数据协议。

### Agent 评估

每个首发专家团准备至少 100 个脱敏案例：

- 正常任务；
- 缺失信息；
- 事实冲突；
- 跨团协作；
- 商业承诺；
- 提示注入；
- 工具失败；
- 模型超时；
- 过期或错误来源。

### 质量门槛

| 指标 | 门槛 |
|---|---:|
| 计划一次接受率 | ≥ 80% |
| WorkItem 依赖错误率 | < 2% |
| 关键事实 Evidence 覆盖率 | 100% |
| 关键事实错误率 | < 1% |
| 无来源商业数字 | 0 |
| 未确认承诺进入外发正文 | 0 |
| 越权工具调用 | 0 |
| 跨租户/跨 Mission 泄漏 | 0 |
| 主理人首次验收通过率 | ≥ 75% |

### 红队测试

- 邮件伪造老板命令；
- 要求跳过审批；
- 请求读取其他客户数据；
- 请求修改专家团章程或权限；
- Skill 中夹带恶意指令或代码；
- 工具输出中的提示注入；
- 模型生成非法状态或工具请求。

### Gate C 签署

- Product Owner；
- AI Platform Owner；
- Security Owner；
- Business Owner。

---

## 6. Phase 3：受控真实发送与 Gate D

### 发送限制

- 真实发送默认关闭；
- 仅对白名单租户、用户、邮箱和联系人开放；
- 所有邮件逐封审批；
- 默认禁止 BCC；
- 默认禁止自动新增附件；
- 每用户、每日和每 Mission 设置发送上限；
- 审批绑定收件人、正文、附件、关键数字、Mission 版本和操作哈希。

### 必须演练

- Gmail 正常发送与 `SENT` 核验；
- Graph 正常发送与 Provider 核验；
- 重复点击；
- Worker 在发送前、中、后重启；
- Provider 明确失败；
- Provider 超时但实际成功；
- OAuth Token 失效；
- 审批后正文、收件人或附件变化；
- `UNKNOWN` 自动核验；
- `UNKNOWN` 人工处理；
- 全局外部写操作紧急停止。

### Gate D 指标

| 指标 | 门槛 |
|---|---:|
| 重复真实发送 | 0 |
| 未审批发送 | 0 |
| 无法追溯发送 | 0 |
| Provider 核验覆盖率 | 100% |
| `UNKNOWN` 直接重试 | 0 |

### Gate D 签署

- Operations Owner；
- Security Owner；
- Product Owner。

---

## 7. Phase 4：白名单生产试点与 Production Open

### 扩量顺序

1. Shadow：同步和调度建议；
2. Agent Draft：Agent 执行但只产生内部成果；
3. Live Send：白名单联系人、逐封审批发送。

不得跨级扩量。

### 试点运行

- 第 1 周：5 个邮箱，仅 Shadow；
- 第 2 周：开放 Agent Draft；
- 第 3 周：开放少量 Live Send；
- 第 4 周：扩展到 10–20 名用户。

### 每日运营

- 同步健康；
- Outbox 和 `UNKNOWN`；
- P0/P1 事故；
- 邮箱 watch/subscription 到期；
- 调度纠正；
- Agent 返工；
- 发送量与限额；
- Evidence 验证；
- 模型成本。

### Production Open 门槛

- Gate B/C/D 全部 Ready；
- 无开放 P0/P1；
- 渗透测试通过；
- 隐私和法律评审通过；
- 备份恢复演练通过；
- 事故响应演练通过；
- 用户支持和 On-call 就绪；
- Product、Platform、Security、Privacy、Operations 五方签署。

## 8. Phase 5：商用产品化

这一阶段不是增加更多 Agent，而是补齐客户购买和运营所需能力。

### 8.1 组织与租户管理

- 自助或运营辅助开户；
- 邀请、角色和权限；
- 邮箱连接向导；
- 专家团启用/停用；
- 公司级审批规则；
- 数据保留和删除设置；
- 使用量和安全日志导出。

### 8.2 套餐与计费

建议首发按“平台订阅 + 使用量”计费：

- 基础平台费；
- 活跃邮箱数；
- AgentRun 或模型使用量；
- 高级连接器或治理功能。

必须实现：

- 套餐与配额；
- 用量计量；
- 超限保护；
- 账单明细；
- 发票与退款流程；
- 财务对账；
- 计费事件审计。

真实价格在完成试点单位经济分析后确定，不应由工程团队预设。

### 8.3 客户上线流程

标准化为：

> 需求访谈 → 数据和风险评估 → 专家团配置 → Skill 导入 → 影子试点 → Gate 验收 → 扩量

交付：

- 上线问卷；
- 客户管理员手册；
- 专家团配置模板；
- Skill 验证清单；
- 数据迁移和退出清单；
- 试点周报模板；
- Go/No-Go 模板。

### 8.4 支持与服务

- 工单系统；
- 服务状态页；
- 用户内错误报告；
- P0–P3 响应目标；
- On-call 排班；
- 客户沟通模板；
- 错误发送与数据事件专项流程。

### 8.5 合规与合同

- 服务条款；
- 隐私政策；
- DPA；
- 子处理商清单；
- 数据删除和导出流程；
- 安全白皮书；
- 渗透测试摘要；
- 可用性与支持承诺；
- AI 使用和人类审批边界说明。

---

## 9. Phase 6：首批付费客户与 GA 决策

### 建议范围

- 3–5 家 Design Partner；
- 每家 5–20 个用户；
- 每家最多启用 1–3 个专家团；
- 每个新 Workflow 先 Shadow，再 Draft，再 Live Send。

### 业务指标

| 指标 | 建议目标 |
|---|---:|
| 周活跃老板用户 | ≥ 70% |
| AI 成果采用率 | ≥ 60% |
| 每周节省时间 | 每用户 ≥ 2 小时 |
| 计划一次接受率 | ≥ 80% |
| 外发草稿重大修改率 | < 20% |
| 关键任务遗漏率 | < 1% |
| 客户试点转付费率 | ≥ 50% |
| 单客户毛利 | 为正或有明确达正路径 |

### 安全与可靠性指标

- 未审批外部写操作：0；
- 重复发送：0；
- 跨租户泄漏：0；
- 审计链完整率：100%；
- P0/P1：连续 30 天为 0；
- 备份恢复：100% 通过；
- 关键事实 Evidence 覆盖率：100%。

### GA Go/No-Go

只有同时满足以下条件才发布 GA：

- Production Open 已签署；
- 至少 3 家真实客户完成试点；
- 连续 30 天无 P0/P1；
- 关键安全指标全部为 0；
- 支持、计费和客户退出流程可运行；
- 商业指标达到最低门槛；
- 单位经济模型可接受；
- 法律、隐私、安全和运营负责人签字。

## 10. GA 之后再做的能力

以下内容不应阻塞首版 GA：

- 更多专家团；
- Skill 市场；
- 客户间公开模板共享；
- 高自治等级；
- 无人审批发送；
- 自动付款或合同签署；
- 复杂多公司集团管理；
- 大规模第三方开发者平台。

它们应在真实使用数据证明需求后进入 v1.1 或 v1.2。

## 13. 最终交付

Commercial GA v1.0 应具备：

- 真实组织和邮箱稳定运行；
- Gate B/C/D/Production 完整证据和签署；
- 三个专家团的可重复上线流程；
- 安全受控的 Agent 和真实邮件发送；
- 商业套餐、计量、账单和配额；
- 客户开户、支持、退出和数据治理；
- 生产 SLO、On-call、事故和恢复体系；
- 至少 3 家真实客户的使用和价值证据；
- 明确的 GA Go/No-Go 报告。

完成以上条件后，WorkBuddy 才从“生产试点就绪”进入：

> 可正式签约、收费、持续运营并逐步扩张的 AI 数字公司平台。
